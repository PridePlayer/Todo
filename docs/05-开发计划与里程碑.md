# 05 · 开发计划与里程碑

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0（第二批交付） |
| 开发方式 | 我在本地写完整 monorepo，你在宝塔执行部署命令 |
| 切片原则 | 每片独立可跑、可点、可验收；**绝不出现"后端做完前端看不见"** |

---

## 0. 工作方式约定（先于技术）

1. **每片一个 git tag**（`v0.M0` … `v0.M8`）。回滚就是 `git checkout v0.M(x-1)`。
2. **数据库迁移只增不改**：只允许"加可空列 / 加表 / 加索引"，不允许改列类型或删列。这样回滚代码不需要回滚数据。
3. **每片交付附三样东西**：改动文件清单、你要执行的命令（编号）、验收动作（3~5 条可点）。
4. **你在服务器上每条命令最多 4 行**，超过就说明我封装得不够，我改 `deploy/deploy.sh`。
5. **不做"完成度 90%"的交付**。某功能没做完就不合进主分支，宁可这一片范围小一点。
6. 我写代码时不联网调用你的服务器；所有部署动作由你执行。若某片必须让你验证真机行为（如闹钟），我会给可复现的步骤而不是"你自己试试"。

## 3. 各片详细计划

### M0 · 地基

**目标**：把"能登录的空壳"跑通，同时把所有后续要用的基础设施一次性铺好（迁移、部署、日志、健康检查）。

**交付文件**

```
pnpm-workspace.yaml, package.json, tsconfig.base.json
packages/core/src/models/{user,session}.ts
packages/core/src/api/client.ts
packages/server/src/index.ts            Fastify 启动 + 中间件（pino/cookie/csrf/限流）
packages/server/src/routes/{health,auth}.ts
packages/server/src/db/{schema.ts,migrations/0001_init.sql}
packages/server/src/cli/{seed-user,reset-password}.ts
apps/web/src/{main.tsx,app.tsx,views/Login.tsx}
apps/web/src/design/tokens.css          直接抄 04 文档 §10
deploy/{deploy.sh,grid.service,nginx.conf.example,env.example,backup.sh,healthcheck.sh}
```

**你能验收**

1. 本地 `pnpm dev` 同时起 5173（Web）与 3000（API），浏览器能登录。
2. 错误密码连输 5 次，第 6 次提示"锁定 10 分钟"。
3. 登录后刷新页面仍保持登录；点登出回到登录页，且 `IndexedDB` 里没有任何遗留库（DevTools → Application 检查）。
4. 部署到服务器后，`https://todo.<域名>/` 能打开登录页，`/api/healthz` 返回 `{"ok":true,"db":"up"}`。

**你要执行的命令**（部署）

```bash
cd /www/wwwroot/todo && git pull && pnpm install --frozen-lockfile
pnpm --filter server db:migrate && pnpm --filter web build && pnpm --filter server build
systemctl restart grid && curl -s localhost:3000/api/healthz
```

**明确不做**：不做注册、找回密码、多用户、邮件发送。

**出口条件**：`free -m` 记录与 `/api/healthz` 的 `rssMB` 已写进部署文档——这是判断 2C2G 是否撑得住的第一个真实数据点。若 `available < 900MB`，此处即触发降级决策（改用现有 5.7 建库）。

### M1 · 待办 + 四象限（纯本地，不联网）

**目标**：先把"交互手感"做对。这一片完全不碰网络，数据只进 IndexedDB，用假数据把四象限拖拽、子任务、撤销打磨到位。

**交付文件**

```
packages/core/src/models/task.ts          zod schema（单一事实源）
packages/core/src/repo/types.ts           仓储接口（sync 版实现留给 M2）
packages/core/src/quadrant.ts             象限换算 + 排序
apps/web/src/db/{dexie.ts,repo.ts}        Dexie 实现 + 迁移
apps/web/src/components/{Row,Checkbox,TagChip,Drawer,QuickAdd,EmptyState,Toast}.tsx
apps/web/src/views/{Quadrant,AllTasks}.tsx
apps/web/src/hooks/{useKeyboard,useUndo}.ts
```

**你能验收**

1. 按 `N` 弹快速新增，只填标题回车即存，连续输入 3 条不用重新点。
2. 四象限里把"买猫粮"从 04 拖到 01，松手即生效；按 `Alt+↑` 也能迁移。
3. 建一个任务并加 3 层子任务；尝试加第 4 层时被拒并提示"最多 3 层"。
4. 删除一条任务，5 秒内点"撤销"能恢复；等 6 秒再点已无效。
5. 刷新浏览器，所有数据与顺序都还在（IndexedDB）。
6. 开始/结束时间填 `23:00 - 01:00`（跨天），列表里显示为"23:00 – 次日 01:00"而不是负数时长。

**明确不做**：不做同步、不做日历、不做重复规则。

**出口条件**：四象限拖拽在 3000 条任务下仍不掉帧（可用脚本注入假数据自测）。这是唯一一片允许"纯本地假数据"的切片。

### M2 · 同步内核（全项目最关键的一片）

**目标**：把 offline-first 跑通。从这一片开始，数据同时存在于本地库与服务端，两端可收敛。

**交付文件**

```
packages/server/src/db/migrations/0002_sync.sql      change_seq 表 + 各表 rev/seq/hlc 列
packages/server/src/routes/sync.ts                   pull / push
packages/server/src/sync/{seq,merge,conflict}.ts     取号、字段级合并、冲突判定
packages/core/src/sync/{engine,queue,hlc}.ts         双端共用引擎
apps/web/src/sync/{webLocks,broadcast}.ts
```

**你能验收**

1. 开两个浏览器标签页，A 改标题、B 改日期，两边都保留（字段级合并生效）。
2. 两页同时改标题，B 页保存后出现红点，进"冲突待决"能看到两个版本并选择。
3. 断网（DevTools → Offline）创建 3 条任务，顶栏显示"离线 · 3 条待同步"；恢复网络 10 秒内变"已同步"。
4. 断网时完成一条任务再取消完成，联网后状态与服务端一致，不出现"复活"。
5. 设置页点"全量重建"，本地库清空并重新拉取，数据完整。

**明确不做**：不做 Outlook、不做日历事件。

**出口条件**：`03` 文档 §7.2 判定矩阵的 15 行逐行有用例通过（见 `06` 的 G 组）。这一片不过，后面全部免谈。

**目标**：日/周/月/列表四视图 + 完整的重复三选项编辑。数据仍是 GRID 自己的（此时还没有 Outlook）。

**交付文件**

**你能验收**

1. 建"每周一三五 09:00 开会"，在周视图里能看到未来 4 周的实例。
2. 改其中周三那一次的时间，选"仅本次"——只有那一天变，其他日期不变。
3. 改系列标题选"本次及后续"——从那天起标题变，之前的不变；原系列的结束日期被正确截断。

**目标**：授权、增量拉取、单次事件双向、重复事件只读。这是全项目风险最高的一片，**范围必须严格按 P0 卡死**。

```
packages/server/src/jobs/{graph-pull,push-outbox}.ts
apps/web/src/views/SettingsCalendar.tsx
apps/web/src/components/{SourceToggle,SyncBanner}.tsx
```

**你能验收**

1. 设置页点"连接 Outlook"，跳微软登录并同意，回跳后显示已连接邮箱。
2. 事件在 1 分钟内出现在周视图；全天的、跨天的、非本地时区的都显示正确。
3. 在 Outlook 网页版新建一个会议，1 分钟内出现在 GRID。
4. 在 Outlook 网页版删除一个会议，GRID 里消失（不是变成"未知事件"）。
5. 在 GRID 里把某个单次事件从 10:00 改到 11:00，Outlook 网页版 30 秒内同步。
6. 点开一个重复事件，编辑按钮显示为"在 Outlook 中修改"，点击跳转 Outlook 网页版。
7. 在数据库里直接 `SELECT access_token_enc FROM calendar_account`，看到的是二进制密文而非可读字符串。

**明确不做**：不做重复事件的增删改回写、不做多微软账号、不做 Graph webhook。

**出口条件**：连续 24 小时运行后，`calendar_account.last_sync_at` 持续更新且 `last_error` 为空。若令牌失效，界面上必须出现红色通栏（这条要在真机上等它自然失效或手动撤销授权验证）。

## 5. 回滚策略

| 场景 | 做法 |
|---|---|
| 代码有问题 | `git checkout v0.M(x-1)` → 重新 build → restart。数据不动（迁移只增不改） |
| 迁移写坏 | 迁移前自动 `mysqldump` 到 `/www/backup/grid/pre-migrate-*.sql.gz`，回滚时导入 |
| Graph 令牌失效 | 无需回滚，界面红条 → 重新授权 |
| 本地库版本不兼容 | 客户端清库重拉（服务端是源，可接受） |
| 2C2G 撑不住 | 升配到 4G，或按 M0 闸门降级为复用 5.7 |

## 6. 我建议你重点盯的三片

- **M2（同步内核）**：所有数据错乱的根源都在这里。G 组用例必须 100% 通过再往下走。
- **M4（Outlook P0）**：范围一旦松口（"顺便把重复事件也做了"），工期和 bug 都会翻倍。
- **M6（Android 提醒）**：真机行为无法在浏览器里验证，必须你自己在手机上确认"闹钟真的响了"。

## 7. 不做的事（避免后期被追加）

不做 iOS、不做桌面客户端、不做团队协作、不做多语言、不做深色模式（P1 之后再议）、不做服务端推送、不做 Graph webhook、不做附件上传、不做 AI 排程。
