## 1. 产品定位与边界

### 1.1 一句话定位

**一个把「今天要做什么」和「今天已经排了什么」画在同一张网格上的个人效率工具。**

三件事在用户脑中本来是同一件事——我有什么要做、日历上已经占了什么、我坚持的习惯今天做了没——但市面上的工具逼用户在三个 App 之间来回切。GRID 的价值不在功能多，而在于**消除切换**：一张统一时间轴 + 一个四象限，待办、日历事件、打卡项同时可见、同时可操作。

### 1.2 设计原则（冲突时的裁决顺序）

1. **同屏即真相**：任何需要「切走再切回来」才能对比的信息，都算设计失败。
2. **一眼可判**：颜色只有一种（克莱因蓝），其余全交给位置、字重、留白——用户不需要记忆颜色语义。
3. **键盘与拇指平等**：桌面端 90% 的操作有快捷键；移动端 90% 的操作在拇指可及区。
4. **不打断**：删除可撤销、同步不弹窗、冲突才打扰。
5. **离线是常态而非异常**：断网时功能不退化，只用状态点提示「未同步」。

### 1.3 明确不做（写进合同，防止范围蔓延）

- ❌ iOS / macOS / Windows 客户端 / 浏览器扩展 / 小程序
- ❌ 团队协作、任务指派、共享清单、评论、@提醒
- ❌ 日历邀请（attendees）、会议室资源、RTC 链接
- ❌ 邮件客户端、笔记系统、附件上传（P2 之后再议）
- ❌ 番茄钟、白噪音、AI 自动排程（P2 候选，不进 P0/P1）
- ❌ 第三方登录（Google/Apple/微信）
- ❌ 多语言（仅简体中文）
- ❌ 服务端推送（改为纯本地闹钟）
- ❌ 打卡社交、排行榜、打卡分享图

## 2. 用户与场景

### 2.1 用户画像

单用户（产品作者本人），但代码结构保留 `user_id`，以便未来扩展为小范围多用户。特征：

- 每天在电脑前 6~10 小时，手机是「移动端的补充屏」
- 日历由公司 Outlook 主导，个人待办散落在便签/微信收藏/脑子
- 有 3~5 个长期习惯要追踪（阅读、运动、复盘）
- 对工具的容忍度极低：慢 200ms 就会放弃，多一次点击就会绕过

### 2.2 三个核心场景故事

**场景 A · 晨间规划（5 分钟，电脑）**
7:50 打开 GRID，默认落在「今天」周视图。左侧时间网格上，Outlook 的三个会议已经铺好（来自凌晨的增量拉取）。右侧是一列没有时间的待办。用户把「写季度复盘」从待办列拖到 15:00–17:00 的空档——它变成一个带时间块的任务，颜色是克莱因蓝描边（待办）而非实心（日历事件），一眼能分清来源。再把「买猫粮」拖进「重要不紧急」象限。
> 关键：待办与日历事件在同一网格上，用**描边 vs 实心**区分，而不是用颜色。

**场景 B · 打断插入（10 秒，任意端）**
开会时老板临时派活。手机上从任意页面双击 FAB（或桌面按 `N`），弹出快速新增：只填标题，回车即存，落到「收集箱」清单、无日期。散会后在四象限里拖到正确位置并补标签。
> 关键：**捕获必须是零决策**。任何强制填字段的快速新增都是失败设计。

**场景 C · 周末复盘（15 分钟，电脑）**
打开打卡总览，看最近 12 周热力图：阅读连续 23 天，运动在周三总是断。点「运动」进详情，趋势图显示周三完成率只有 40%。于是把运动的重复规则从「每天」改成「周一/二/四/五/六」，结束条件设为「永不」。
> 关键：数据要能**直接导向动作**，而不是只给一堆漂亮图表。

## 3. 功能需求与优先级

优先级定义：**P0 = 没有它产品不成立**；**P1 = 第一批上线后 4 周内补齐**；**P2 = 有更好，不做也行**。

### 3.1 待办事项

| ID | 需求 | 优先级 | 验收口径 |
|---|---|---|---|
| T-01 | 新建待办：标题（必填）、备注、日期、开始/结束时间、地点、重复、提醒、优先级、标签、清单 | P0 | 仅填标题即可保存；其余字段均可后补；保存后 100ms 内出现在列表 |
| T-02 | 编辑待办（含行内编辑标题、抽屉编辑全字段） | P0 | 行内改标题回车即存，无需打开抽屉 |
| T-03 | 删除待办（软删） | P0 | 删除后 5 秒内可「撤销」；5 秒后从视图消失但 30 天内可从未删除区恢复 |
| T-04 | 完成 / 取消完成 | P0 | 单击复选框即完成；完成后按当前排序规则移出「未完成」区，不产生跳变动画 |
| T-05 | 多级子任务（最多 3 层） | P0 | 父任务显示 `3/5` 进度；父任务完成时子任务一并标记完成（可撤销）；子任务独立显示在「今天」时带父级面包屑 |
| T-06 | 清单（List）管理：新建、重命名、排序、删除（删除时任务移到收集箱） | P0 | 清单仅一层，不支持嵌套（见 §8 待确认 Q2） |
| T-07 | 标签管理：新建、改名、删除（软删）、多标签 | P0 | 标签不限数量；一个任务可挂多个标签 |
| T-08 | 筛选：来源（待办/事件）、类型、清单、标签、完成状态、优先级、日期范围 | P0 | 筛选条件可组合，且刷新后保留（写入本地偏好） |
| T-09 | 排序：手动（拖拽）、日期、优先级、创建时间、字母 | P0 | 手动排序在「今天」以外视图只对同组内生效 |
| T-10 | 搜索：标题 + 备注 + 标签 | P0 | 输入即搜（防抖 150ms），本地库检索，1000 条内 < 50ms |
| T-11 | 四象限视图 + 拖拽调整象限 | P0 | 拖拽落点即时生效；支持键盘 `Alt+箭头` 迁移；象限由 `important`/`urgent` 两个布尔决定 |
| T-12 | 批量操作：多选后完成 / 删除 / 移动清单 / 打标签 | P1 | 桌面 `Shift+点击` 连选；移动端长按进多选 |
| T-13 | 待办「延期」快捷操作（+1 天 / 下周一 / 自定义） | P1 | 右键菜单与滑动操作均提供 |
| T-14 | 归档：完成超过 N 天（默认 30）自动进归档视图 | P1 | 归档不影响统计与搜索（可搜到） |

### 3.2 重复规则

| ID | 需求 | 优先级 | 验收口径 |
|---|---|---|---|
| R-01 | 基础重复：每天 / 每周 / 每月 / 每年 / 工作日（周一至周五） | P0 | 生成规则可被 iCal RRULE 无损表达 |
| R-02 | 自定义每周内多选（如周一/三/五） | P0 | 至少选 1 天；保存后下一次出现日期计算正确 |
| R-03 | 结束条件：永不 / 指定日期结束 / 重复 N 次结束 | P0 | 三者互斥；选「N 次」时显示"共 N 次，将于 X 结束" |
| R-04 | 编辑范围三选项：仅本次 / 本次及后续 / 全部 | P0 | 仅本次 → 生成 exception（RECURRENCE-ID + EXDATE）；本次及后续 → 截断原系列 + 新建系列；全部 → 改 master |
| R-05 | 删除重复任务的范围同样三选项 | P0 | 「仅本次」写 EXDATE；不产生孤儿 |
| R-06 | 时区与夏令时正确性 | P0 | 以任务创建时的 `tzid` 为准展开；跨 DST 不出现"少一次/两次" |
| R-07 | 按月重复的两种模式：按「第几日」或按「第 N 个周几」 | P1 | 例：每月 31 日（无 31 日的月份跳过）vs 每月最后一个周五 |
| R-08 | 重复任务「提前 N 天生成」开关（用于给未来实例单独加备注） | P2 | 默认关闭 |

> **注意**：R-04 的「本次及后续」是全项目最贵的单点功能，PRD 只定义行为，实现细节见 03 文档 §5。

### 4.3 核心流程

**流程 1 · 首次使用**
```
登录 → 设置主密码 → 「连接 Outlook」→ 跳微软授权 → 回调成功
→ 后台全量拉取（进度条，可关掉继续用）→ 自动建「收集箱」清单
→ 引导页 3 屏（可跳过）→ 落到「今天」
```

**流程 2 · 从任意视图快速新增**
```
触发（N / 双击 FAB）→ 浮层聚焦标题输入框 → 输入标题
→ [回车] 只存标题，落「收集箱」，浮层留在原位可继续输入下一条
→ [Tab] 展开更多字段（日期/时间/清单/优先级）
→ [Esc] 关闭；有内容时二次确认
```

**流程 3 · 重复任务改「仅本次」**
```
打开重复任务 → 改日期 → 出现范围选择条「仅本次 / 本次及后续 / 全部」
→ 选「仅本次」→ 原实例生成 exception（RECURRENCE-ID），系列写 EXDATE
→ 若该任务已同步 Outlook：pending 状态点 → 回写队列 → 成功后转实心
```

**流程 4 · 离线创建 → 联网同步**
```
断网创建任务 → 顶栏转黄「离线 · 3 条待同步」→ 本地正常可用
→ 恢复网络 → 自动 flush（指数退避）→ 逐条 push，带 op_id 幂等
→ 成功则转灰「已同步」；失败则红点，点开看原因（可重试/丢弃）
```

**流程 5 · 冲突**
```
远端与本地改同一字段 → 服务端判冲突 → 非冲突字段自动合并
→ 冲突字段保留双方值 → 客户端出现红点 → 用户在三栏对比页选择
→ 选择写入本地 + 推服务端 + 记录 conflict_log
```

**流程 6 · 打卡**
```
打卡总览 → 点习惯卡片上的「+1」→ 当日进度 +1/1 → 勾满
→ streak 重算 → 热力图末格点亮 → 若设了提醒，次日闹钟已排程
```

## 5. 关键交互规则（可直接作为开发依据）

### 5.1 重复编辑的三选项

- 触发条件：对象是重复系列的实例。
- 展示形态：桌面为编辑抽屉顶部的分段控件；移动端为底部操作条。
- 文案：「仅本次」/「本次及后续」/「全部 N 次」。
- **默认焦点在「仅本次」**——破坏性最小。
- 「全部」为危险操作，需在按钮下方给出影响说明：「将修改全部 23 次」。
- 若选择「本次及后续」，且原系列有已修改的例外实例，弹出提示：「后续 5 次中有 2 次被单独修改过，是否保留？」

### 5.2 删除

| 场景 | 交互 |
|---|---|
| 单条删除 | 立即删除 + 底部 Toast「已删除 · 撤销」，5 秒 |
| 批量删除（≥2） | 先弹确认对话框，列出条数与前 3 条标题，红色主按钮 |
| 删除重复系列 | 弹范围选择，同 5.1，选「全部」需二次确认 |
| 删除清单 | 确认对话框说明「其中 12 个任务将移动到收集箱」，不删任务 |
| 删除日历事件 | 二次确认 + 说明「将同时从 Outlook 删除」 |

不允许出现：无提示的永久删除；「确定/取消」语义模糊的对话框（按钮必须是动词：「删除」「保留」）。

### 5.3 时间轴与重叠

- 吸附粒度 15 分钟；按住 `Alt` 临时取消吸附。
- 事件块最小高度 22px（不足时显示为细条 + tooltip）。
- 重叠算法：同时段事件按开始时间排序，采用列分配（column packing），最多 3 列，第 4 个起并入「+N」。
- 待办块与事件块可重叠（不在同一列分配体系内），待办块半透明叠加在事件块之上，避免遮挡。

### 5.4 状态提示

| 状态 | 位置 | 表现 |
|---|---|---|
| 同步中 | 顶栏右侧单点 | 克莱因蓝小圆点脉冲 |
| 已同步 | 同上 | 灰色实心点，鼠标悬停显示「刚刚同步」 |
| 离线 | 顶栏通栏 2px 黄线 + 右侧文字「离线 · N 条待同步」 | 不弹窗、不遮内容 |
| 同步错误 | 同上转红 + 点击展开原因 | 需用户显式处理 |
| 令牌失效 | 通栏红色条 + 「重新授权」按钮 | 不可自动关闭 |
| 加载 | 内容区骨架屏 | 骨架与实际布局同构，避免跳变 |
| 空 | 内容区居中 | 一句话说明 + 一个主行动 |

### 5.5 快速新增的语法（P1）

标题内支持轻量标记，保存时解析并剥离：

- `#标签` → 打标签（自动创建）
- `@清单` → 归入清单
- `!1` ~ `!4` → 优先级
- `明天 15:00`、`下周一`、`每周三` → 解析为日期/重复

解析失败时**不报错**，原样作为标题保存。

## 7. 遗留风险与产品侧对策

| 风险 | 产品侧对策 |
|---|---|
| Outlook 重复事件 P0 只读，用户会困惑 | 详情页明确显示「重复事件暂不支持在 GRID 内编辑」+ 「在 Outlook 中打开」按钮，并在首次遇到时一次性提示 |
| 个人微软账号 refresh token 可能失效 | 一旦失效，顶部红色通栏常驻，不允许忽略；设置页显示令牌最近刷新时间 |
| 2C2G 内存紧张 | 前端不做全量预加载；视图切换按需拉取 ±3 天窗口 |
| Android 国产 ROM 杀后台闹钟 | 首次设置提醒时给出「请将 GRID 加入电池白名单」的图文引导（可跳过） |

## 8. 仍需确认的问题清单（我已给出默认值，若你不反对就按默认执行）

| # | 问题 | 我的建议默认值 | 影响 |
|---|---|---|---|
| Q1 | 打卡是否允许「1 天宽限」不断 streak | **不允许**（严格连续），但提供「周末不计入」开关 | 宽限会让连续天数失去意义；周末开关更贴近真实习惯 |
| Q2 | 清单是否支持嵌套 | **不支持**，仅一层 | 嵌套会显著复杂化筛选与拖拽 |
| Q3 | 子任务层级上限 | **3 层** | 4 层以上在移动端无法有效展示 |
| Q4 | 已完成任务多久进入归档 | **30 天** | 影响「全部待办」的默认查询性能 |
| Q5 | 是否做深色模式 | **P1**（P0 只做浅色） | 瑞士风格在浅色下更纯粹；深色需重做一整套灰度 |
| Q6 | 甘特视图的分组维度 | **按清单分组**（可切按标签） | 按标签分组时一个任务会出现在多行 |
| Q7 | 事件重叠超过 3 个的展示 | **第 4 个起折叠为「+N」，点击展开并排** | 并排无限列会挤成 20px 宽不可读 |
| Q8 | Outlook 是否同步全部日历 | **同步全部「可见」日历，可在设置里排除** | 生日/节假日日历混进来会污染视图 |
| Q9 | 拖拽改期的回写时机 | **松手后 3 秒防抖**，再 PATCH | 逐帧 PATCH 会触发 Graph 限流 |
| Q10 | 密码找回方案 | **不做自助找回**，用服务器端 `reset-password` 命令重置 | 单用户场景下自建邮件服务是过度设计 |

## 9. 术语表

| 术语 | 含义 |
|---|---|
| 清单（List） | 任务的容器，仅一层，类似「项目」 |
| 系列（Series） | 一个重复事件/任务的母体，对应 iCal 的 master |
| 例外（Exception） | 系列中被单独修改的某一次，对应 RECURRENCE-ID |
| 跳过期（EXDATE） | 系列中被删除的某一次 |
| 待安排（Unscheduled） | 只有日期（或没有日期）、没有具体时间段的任务 |
| 收件箱 / 收集箱（Inbox） | 默认清单，快速新增的落点 |
| 投影（Projection） | GRID 本地数据在 Outlook 侧的表示；Outlook 不是真源 |
| change_seq | 服务端全局单调递增的变更序号，增量同步的水位线 |
